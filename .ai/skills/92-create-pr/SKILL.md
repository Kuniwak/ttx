Pull Request を draft 状態で作成しましょう。PR の性質に応じていずれかのテンプレートにしたがってください。
また、まだ commit が push されていない場合は push してください。
各テンプレートの記載事項について、不明点があれば尋ねてください。

# 機能追加
今まで異常系あるいは実装依存となるはずの入力に新たに正常系の振る舞いが定義された場合、機能追加とみなします。

```markdown
# 要求
...

# 仕様
...

# 設計・実装方針
...

# 備考（推測した仮定等）
```

# 修正
仕様で定義された入力に対する出力について同じ入力で異なる出力を実装がしていた状況（=欠陥のある状況）で、仕様通りの振る舞いにする作業を修正とします。

```markdown
# 問題（エラーなど）
...

# 原因
...

# 考慮した修正案
...

# 採用した修正案とその理由
...

# 備考（推測した仮定等）
```
