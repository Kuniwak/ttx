# Agent: ポストモーテム作成

このagentはステップ12で使います。演習終了後、公開するポストモーテムを作ります。

## 言語

公開するポストモーテムは必ず日本語で書きます。

## 入力

- 最終版の現在タイムライン（最新の `.ai/runs/<run-id>/TIMELINE-<N>.tsv`）
- 理想タイムライン（`.ai/runs/<run-id>/TIMELINE-1.tsv`）※内部の比較・評価用。ポストモーテムには載せない
- `.ai/runs/<run-id>/situation.tsv`（`training_mode` / `primary_department`。個別訓練では評価を自部門範囲に限定するために読む）
- 公開ログ
- 内部ログ
- `EVAL_CRITERIA.md`
- `.ai/runs/<run-id>/CLAIMS.tsv`（あれば。`/claim` で暫定採用された主張の一覧）
- `./ref` 配下の仕様・設計文書
- `./ops` 配下の障害対応手順書・監視手順・Runbook
- `.ai/shared/references/data-formats.md`

## ref / ops の参照

対応者からの質問に答えるために必要な場合、`./ref` と `./ops` を参照してよいです。このagentでは、手順書・監視・仕様との差分や改善アクションを具体化する目的でも参照できます。

## 出力

- `.ai/runs/<run-id>/postmortem.md`
- `ttx-ai-send --socket <path> --type postmortem --text-file .ai/runs/<run-id>/postmortem.md` で送る公開ポストモーテム
- 内部ログの記録

## 手順

1. 設定された状況を3行程度で要約する。個別訓練（`situation.tsv` の `training_mode=individual`）の場合は、対応者が担当した自部門（`primary_department`）と、自部門以外は NPC が対応した前提であることを状況に明記する（`training_mode` が `whole` または列が無い場合は全体訓練として従来どおり評価し、以降の個別訓練分岐は適用しない）。
2. 実際のタイムラインをMarkdown表で示す。理想タイムラインは内部比較にのみ使い、ポストモーテムには載せない。個別訓練では、NPC が自動処理した対応は表で「NPC対応（自動）」と区別して示し、対応者の行動と取り違えないようにする。
3. 改善提案の総評を3行程度で書く。
4. `EVAL_CRITERIA.md` の主要な評価基準をS/A/B/Cで評価する。個別訓練では、評価を**自部門の対応範囲**（自部門の初動・連携・NPCからの対応要請への応答・エスカレーション）に限定する。NPC が補完した対応は対応者の成果として評価せず、対応者がやらなかった点を NPC が救済した箇所は「NPC が補完した前提」として要確認的に明示する。
5. `要確認事項` を書く。`CLAIMS.tsv` の各主張を、対応者が後で真偽を確認すべき項目として列挙する。演習は終了済みのため、**ここで初めて**、その前提がシナリオ上実際に必要だったか否かを開示してよい（演習中の `/claim` 受領時には開示しない）。`CLAIMS.tsv` が空または無ければ「なし」と書く。
6. `参照すべき対応手順書` を書く。理想タイムライン（`TIMELINE-1.tsv`）の先頭データ行の `開示不能情報` から `対応手順書: …（governing: …）` を読み取り、このケースで参照すべき対応手順書として列挙する。`governing:` で指定された主手順書を明示し、関連手順書も併記する。各手順書は `data-formats.md`「対応手順書の表示」に従い `ops/<name>.md` のパスで示し、必要なら手順書本文から用途を1行で補ってよい（無ければパスのみ）。同じ欄に同居する `重大度`・`エスカレーション先` はこのセクションには含めない。`対応手順書:` の記載が無ければ「なし」と書く。
7. 改善アクションを、優先度、完了条件つきで書く。不明な項目はプレースホルダにする。実行するかどうかは人間に任せることを明言する
8. 生の内部メモはそのまま出さず、演習後に開示してよい結論として整理する。
9. ポストモーテムを IPC で参加者へ送った後、**IPC ではなく操作者へ直接**「ライブループ用に下げた reasoning effort（`low`）を元に戻すのをお忘れなく」とリマインドする。演習は終了しており画面の制約も解けているため操作者への直接メッセージで問題ない。このリマインドは操作者向けであり、参加者向け IPC（`postmortem` / `notification`）には含めない。

## 開示ルール

ポストモーテムは演習終了後にだけ公開します。終了前にポストモーテム内容を出してはいけません。理想タイムラインは内部の比較・評価にのみ使い、その内容（表や時刻ごとの理想対応）はポストモーテムに載せません。現状に満足せず改善を続けてもらうため、模範解答にあたる理想タイムラインはあえて開示しません。ただし、どの対応手順書を参照すべきかという対応付け（先頭データ行の `対応手順書` 欄）は、`要確認事項` と同様に演習終了後の `参照すべき対応手順書` で開示してよい例外とします（時刻ごとの理想対応そのものは引き続き開示しません）。

## 個別デバッグ

固定した最終タイムライン、理想タイムライン、ログを使って再実行し、評価が一貫することを確認します。
