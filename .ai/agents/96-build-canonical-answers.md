# Agent: 想定回答集作成（canonical）

このagentは `.ai/skills/92-build-scenario/SKILL.md` の**想定回答集作成の段**で使います。想定質問に対する回答案を、理想タイムラインにもとづいて作り `timelines/<新ID>/ANSWERS-1.tsv` として保存します。

演習用 agent `.ai/agents/04-build-expected-answers.md` と同じ作業を canonical 正本に対して行います。「回答に使えるのは質問時点で観測可能な事実だけ」「手がかり・推測・誘導・設計説明の禁止」は `04` に従い、ここでは重複定義しません。

## 言語

回答文はすべて日本語で書きます。

## 入力

- `timelines/<新ID>/QUESTIONS-1.tsv`
- `timelines/<新ID>/TIMELINE-1.tsv`
- `OBSERVATION.tsv`
- `./ref` 配下の仕様・設計文書、`./ops` 配下の障害対応手順書（観測可能・開示可能かの判断に使う）
- `.ai/shared/references/data-formats.md`

## 出力

- `timelines/<新ID>/ANSWERS-1.tsv`（列: 時刻 / 質問 / 回答。`時刻`／`質問` は質問集を維持し `回答` 列を加える）
- 内部ログの記録

## 手順

1. `QUESTIONS-1.tsv` の `時刻`・`質問` を維持し `回答` 列を加える。
2. 質問時点で知りうる観測情報と、現在または過去のタイムライン上の事実だけを使って回答する。観測可能な事実の提示に留め、原因・影響の推測や次にやるべき切り分け・調査手順の提案・誘導は含めない。
3. 隠し情報・未来情報、または設計・仕様・用語の説明を聞かれたら、説明せず「現時点ではわかりません」「お答えできません」と答える。
4. 回答は観測事実を端的に書く（通常1〜3文）。
5. **RP-1 の温存ニュアンス**: 「〜が必要」に見えても、それが観測可能な事実・記録・登録済み改善チケットの内容・業務事実なら温存し、参加者への次手順の誘導だけを除く（過剰除去を避ける）。

## 開示ルール

回答案は開示レビュー（97）が終わるまで内部情報です。観測可能な事実の提示に留め、GM 自身の推測・仮説・次手順の提案・誘導を含めません。

## 個別デバッグ

固定した `QUESTIONS-1.tsv`・`TIMELINE-1.tsv` で再実行し、97 のレビュー結果と比較します。
