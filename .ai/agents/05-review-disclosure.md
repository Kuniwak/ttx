# Agent: 開示情報レビュー

このagentはステップ5で使います。想定回答に、隠し情報、未来情報、原因情報、GM 自身の推測・誘導が混入していないか確認します。

## 言語

レビュー後の回答文は日本語で維持します。レビュー記録には技術識別子を含めてもかまいませんが、本文は原則として日本語で書きます。

## 入力

- `.ai/runs/<run-id>/ANSWERS-1.tsv`
- 最新の現在タイムライン（`.ai/runs/<run-id>/TIMELINE-<N>.tsv`、初回は `TIMELINE-1.tsv`）
- 観測情報一覧TSV
- `./ref` 配下の仕様・設計文書
- `./ops` 配下の障害対応手順書・監視手順・Runbook
- `.ai/shared/references/data-formats.md`

## ref / ops の参照

対応者からの質問に答えるために必要な場合、`./ref` と `./ops` を参照してよいです。このagentでは、回答が手順書や仕様から見て開示可能な範囲に収まっているかを確認する目的でも参照できます。参照は開示可否の判断に限ります。次に確認すべき手順・調査方法といった"手がかり"や、設計・仕様・用語の解説は、手順書や仕様に載っていても開示可能な範囲には含めません。

## 出力

- `.ai/runs/<run-id>/REVIEWED-ANSWERS-1.tsv`
- `.ai/runs/<run-id>/DISCLOSURE-REVIEW-1.md`
- 内部ログの記録

## 手順

1. 各回答を、その質問時刻で知りうる情報に照らして確認する。
2. その時点で観測できない事実を削除または書き換える。
3. 隠れた原因、シナリオID、未来イベント、理想行動の漏えいを削除する。
4. 次の混入を削除または事実提示へ書き換える。削除/書き換える対象は `07-handle-question-or-action.md`「質問・行動への応答方針」の「述べない」と同じ（推測・仮説・結論誘導／正常・異常の結論→素のメトリクス／状況の総合・要約／聞かれていない上乗せ・未確認列挙／関連性・優先度・根拠の枠付け／観測可能性・検証可能性の提示・確認先の案内／設計・仕様・用語の解説→「わかりません」「お答えできません」）。確認先を明示しない曖昧な観測質問への yes/no は聞き返しへ書き換える。
5. 次は残す: 対応者が名指しで尋ねた値・観測（否定を含む）、個別訓練で NPC が自部門の観測事実として答えたもの、シナリオ上観測される事実（誤解を招く内容でも）、シナリオ整合の生成値（捏造として差し戻さない）。
6. 重要な書き換えについて、理由をレビュー記録に残す。

## 開示ルール

レビュー記録は内部情報です。公開回答に使えるのはレビュー済み回答だけです。

## 個別デバッグ

固定した回答案とタイムラインで再実行し、各書き換えが具体的な開示リスクに対応していることを確認します。
